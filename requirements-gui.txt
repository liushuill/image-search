-r requirements.txt

PySide6>=6.6.0,<6.12
# ⚠️ 6.12.0 在 Windows 上有一个**可复现**的退出崩溃（2026-10 实测）。
#
# 现象：用例全过，进程退出时 0xC0000409（= abort，崩在 ucrtbase.dll），
#       pytest 侧没有任何 traceback，进度条走完就没了。
#
# 已缩到具体范围（同一份代码，只换 Qt）：
#   · 最小用例「1 个 QWidget + QApplication」→ exit=0，不崩
#   · tests/test_gui_prefs.py 按类拆开 6 个类 → 只有 TestUnsavedChangesGuard 崩
#   · 该类 9 个用例**逐个单跑** → 全部 exit=0
#   · 该类 9 个用例**一起跑** → 3/3 崩
#   · 该类**不含任何线程**（只涉及引擎页表单、QMessageBox monkeypatch、页面切换）
#     → 因此不是「缩略图线程收尾」那个问题，是另一回事
#   · 与图形平台无关（offscreen / minimal 都复现），只是概率不同
#
# 特征：**累积型**。单跑不炸，累积到一定量的控件/对话框之后才炸。
# 根因未定位 —— 可能是我们的对象泄漏（对话框没设 parent、信号重复连接），
# 也可能是 Qt 自身的 bug。
#
# 现状：6.11.2 上全量测试 exit=0，故限制保持。等定位根因再评估放开。
#
# ✅ 已排除「只是低完整性会话的产物」这个可能（2026-10-26 复测）：
#    正常目录 + Medium 完整性（S-1-16-8192）+ 完整桌面，6.12.0 **3/3 崩**，
#    6.11.2 **3/3 exit=0**。所以这条限制针对的是真实用户会遇到的问题，
#    不是受限环境的保险。
#
# 详细证据与复现条件见 README「常见问题 → PySide6 6.12 退出时崩溃」。
